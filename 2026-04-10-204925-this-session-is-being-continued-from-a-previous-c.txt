  2. Flow samples a residual Δaa, then reconstructs: aa_sample = aa_3dofs + Δaa
  3. Back to euler via convert_flow_samples_to_mhr_params:
  aa_sample → axis_angle_to_matrix → rotmat → extract euler → 130D pose

  This is self-consistent — the same aa_3dofs is used for both the residual
  addition and the context conditioning.

  The NLL loss path uses a different chain for the mean AA:
  body_pose (euler) → batch6DFromXYZ → rotmat → matrix_to_axis_angle →
  mean_AA_euler

  These two mean AAs (aa_3dofs from 6D vs mean_AA_euler from euler) represent
  the same rotation but can differ numerically because of the extra euler
  extraction roundtrip in path 2 (rotmat → atan2 → euler → batch6DFromXYZ →
  rotmat). Near gimbal lock or branch cuts, atan2 can return a different euler
  representation, and the roundtrip back through batch6DFromXYZ may not
  perfectly recover the original rotmat.

  However, this only causes a small bias in the NLL loss target — the residual
  gt_AA - mean_AA_euler is slightly different from the residual the flow
  actually produces at inference (sample - aa_3dofs). In practice, the
  reprojection losses (kp2d/kp3d) dominate training and are computed on the
  self-consistent sampling path, so this bias has minimal impact.

  The debug block amplified this into a visible error because it used
  mean_AA_euler for the residual but aa_3dofs for the addition, so aa_3dofs + 
  (gt_AA - mean_AA_euler) ≠ gt_AA when the two mean AAs disagree.

     Plan: Fix euler↔AA branch-cut bias in NLL loss (Issue 1)

     Context

     The NLL loss computes the mean prediction's 3DOF pose AA via a different
     path than the sampling code, introducing a systematic bias of mean=0.095,
     max=2.82 radians in AA space (~95% of typical residual magnitude).

     Sampling path (correct, used at inference):
     pred_pose_raw (6D continuous) → Gram-Schmidt → rotmat →
     matrix_to_axis_angle → aa_3dofs

     NLL loss path (biased, used for training target):
     pred_pose_raw → compact_cont_to_model_params_body → body_pose (euler)
       → batch6DFromXYZ → rotmat' → matrix_to_axis_angle → aa_3dofs'

     The extra euler roundtrip in the NLL path (rotmat → atan2 → euler →
     batch6DFromXYZ → rotmat') can land on a different atan2 branch, causing
     rotmat' ≠ rotmat and therefore aa_3dofs' ≠ aa_3dofs. The flow is trained on
      residuals gt_AA - aa_3dofs' but at inference adds residuals to aa_3dofs,
     so the mismatch biases the NLL target.

     The same issue exists in initialize_actnorm.

     Replace the euler-based mean AA computation with the direct 6D→AA path
     (convert_pose_cont_to_flow_context) in both nf_loss.py and
